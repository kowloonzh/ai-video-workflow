# 第 1 步：从一个想法到定稿剧情

用户带着一个想法或初步剧情来，你和用户一起聊、一起完善，直到完整故事定稿。有不清楚的地方就问，**用户确认后**再展开成逐镜头故事。

## 结构选择

- **首选片段式**：每个镜头之间不用接戏，最稳。
- **连贯式**最容易穿帮（衣服、道具、位置、光线都要前后对上），除非用户要求，否则不用。用了就要在分镜里额外写清每一镜的衔接状态。

## 好故事的 5 条标准

1. **符合现实逻辑**。每个转折都按现实追问一遍：为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？（用户明确要超现实的除外，但超现实也要自洽。）
2. **能用一句话说清想表达什么**。先把这句话写出来。说不出来，或者说出来很平，就说明故事还要改。也问一句：哪段剧情设计得最好？
3. **开头就要抓人**。观众看几秒就可能划走，最抓眼球的画面放在最前面，写清楚第几秒出现什么。
4. **旁人的反应要像真人**。每个包袱或转折都分 3 段写：**问题 → 主角怎么解决 → 旁人什么反应**。
   - 反应要有先后。几个人同一秒做同一个动作（比如同时举手），一看就是 AI 做的。
   - 细节要真实，比如真人吃惊时身体会往后缩。
5. **AI 要拍得出来**。避开 AI 视频的固定弱点：
   - 人物交叉、人物遮挡后再出现
   - 手拿小东西、精细的手部操作
   - 文字（招牌、纸条、屏幕内容）
   - 镜子和倒影
   - 左右不对称的特征（容易左右翻转）
   - 一个镜头里换光（开灯、闪电、日落）
   - 一个人连做三个动作
   - 俯拍看不到脸
   - 配角太多

   实在需要这些画面，就换个拍法（比如文字后期加，换光放在切镜处），并在故事里标注"高风险"。

## 配歌

如果配歌：转折对上副歌，关键动作对上重拍。先记下歌名、时长、BPM，后面按小节算时间。

## 给用户的开工提示词（用户也可以直接把这段发给你）

```
我想做的片子：[一句话，或者我的初步剧情]。片长：[秒]。
配歌：[歌名、时长、BPM；不配歌就删掉]。
参考片：[有就写，没有就删掉]。

先帮我把这个想法完善成一个完整的故事。有不清楚的地方就问我，我们一起聊，等我确认了再往下写。
故事结构首选片段式；连贯式最容易穿帮，除非我要求，否则不要用。

故事确定以后，展开成逐镜头的故事，要满足：
1. 符合现实逻辑（每个转折按现实追问）。
2. 能用一句话说清想表达什么，先写出这句话。
3. 开头就要抓人，写清第几秒出现什么。
4. 旁人的反应像真人：问题 → 主角怎么解决 → 旁人什么反应；反应有先后。
5. 让 AI 拍得出来，避开已知弱点。
如果配歌，转折对副歌，关键动作对重拍。
```

## 逐镜头故事的格式（存成 `01-story/story-vN.md`）

```
一句话主题：……
结构：片段式 / 连贯式
总时长：…秒（配歌：…BPM，共…小节）

镜头 01｜约 X 秒｜[配歌时写第几小节]
发生什么：……
问题 / 解决 / 反应：……（只在有包袱的镜头写）
风险：……（命中了哪条 AI 弱点，没有就写"无"）
```

## 关卡：独立 agent 审故事

故事定稿后，新开一个 agent（例如用 Agent 工具），**只给它定稿的逐镜头故事文件**，不给聊天记录、不给其他文件、不给你的结论。审核提示词：

```
这是一支短片的逐镜头故事。你是第一次看，只负责挑错，不改文件。
1. 只按镜头顺序读，先写出你看懂的故事。
2. 按顺序追问每个转折：为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？
3. 能用一句话说清想表达什么吗？
4. 开头抓人吗？最抓眼球的画面放在前面了吗？
5. 旁人的反应像真人吗？有没有先后？
6. 哪些镜头 AI 视频模型容易拍错？（人物交叉、手拿小东西、文字、镜子和倒影、左右不对称的特征、一个镜头里换光、一个人连做三个动作、俯拍看不到脸、配角太多）
每条写：镜头、问题、建议改法。没把握的写"可能"。最后写"通过"或"不通过"。
```

拿到审核结果后：先对比审核"看懂的故事"和你想讲的故事，不一致的地方就是没讲清楚的地方。把问题和你建议的改法汇报给用户，改完存新版本。改动大的话重新审一遍。审核"通过"、用户确认后，剧情才算定稿。
