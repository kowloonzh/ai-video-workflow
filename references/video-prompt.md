# 第 5–6 步：视频提示词、提交前审核、生成

生成的画面有问题，很多时候不是模型不行，而是提示词写得不够细。出了问题**先怀疑提示词**，再怀疑模型。

## 七段式提示词模板

每镜固定用这个结构，把每一秒发生什么都写出来。存成 `05-prompts/shotNN/prompt-vN.txt`。

```
【画风】[直接复用 03-style/style.md 里那句话]。整段的画风、颜色、人物设计与首帧和尾帧完全一致。
【镜头】整段 [X] 秒，[景别]，[机位]，[运镜；不动就写"不推不拉不摇，不切镜"]。
【构图与配色】[人和东西在画面哪里，墙和光是什么颜色，要和首帧对得上]
【人物】[每个人的长相、衣服、固定道具，从 characters.md 逐字复用]
【逐秒】
0–0.2 秒：画面完全静止，和首帧一模一样。
[每一段：谁做什么，表情怎么变，手放在哪、不能碰什么，往画面哪边]
最后 0.3 秒：所有人完全停住，画面与尾帧完全一致。
【声音】只有 [看得见声源的声音]。人物不说话。
【约束】画面里一直只有首帧这几个人和这些东西，脸和身形全程不变，一镜到底。画面干干净净，没有文字、字幕、水印。
```

要点：
- 每镜只写一两个主要动作。动作一多就乱。
- 时间只能算大概，多留一点余量，后期再用剪辑和变速对上节拍。
- 平台有字数限制时，先保证【逐秒】和【约束】，【画风】和【人物】可以压缩，但关键词不能变。
- 英文提示词效果更好的模型，就把定稿的中文版翻成英文提交，两版都存。

## 模型最容易犯的错，以及有效写法

写完提示词后对着这张表逐条查：

| 模型容易犯的错 | 应该怎么写 |
|---|---|
| 一群人同时做同一个动作 | 写清楚先后："老爸第一个……过一两秒老奶奶才……小女孩最后……"，首帧也不要摆同一个姿势 |
| 本该风做的事，人自己动手做了（比如邮差用手掀开邮包） | 写清楚原因，再加"两只手从头到尾都没有碰邮包" |
| 云、月亮、植物长出眼睛和嘴巴 | 不写"卡通云"，写"蓬松的灰白色积云，只有棉絮一样的纹理和阴影"，动作也只写它怎么移动 |
| 人往反方向走 | 按画面写方向："朝画面左边走，跨过左边的店门" |
| 一句话有两种意思（"窗户后面的老人"，结果车里冒出人） | 写得更具体："左上角石头房子的窗口里"，再加"驾驶座一直空着" |
| 东西的数量变了 | 把数量直接写出来："只有一封黄信封，之后他怀里全是白信封" |
| 写"不要怎么样"经常没用（写了"壶嘴不出水"还是出水） | 尽量改成正面说法："画面里一直只有首帧这几个人" |
| 模型会自己联想道具的用法（壶总是出水） | 干脆不让这个道具出现在有动作的镜头里 |
| 东西凭空出现 | 只用首帧里已经有的东西 |
| 东西突然飞走或瞬间移动 | 写清楚运动过程："顺着后脑勺往后一滑，接住，扣回头上" |
| 雨、帽子、纹身拍着拍着就没了 | 首帧和尾帧都画上 |
| 闪电画得太写实 | 写"云里闪一下白光"，再把开头剪掉 |
| 一个镜头动作太多就乱了 | 每镜只写一两个主要动作 |
| 动作时间和写的不一样 | 时间只当大概，多留余量，后期剪辑变速 |
| 推镜头没有写的那么明显 | 后期用代码再推一点（缓慢缩放裁切） |
| 人的嘴自己在动 | 写明"人物不说话"，还动就用代码修 |

具体模型的怪癖（比如 Seedance 2.5 / 2.0 mini）见 `model-quirks.md`。

## 关卡：提交前审核（每一条视频都要）

这是抽卡率能压得很低的关键。审核能查出很多肉眼容易漏的问题，例如两张图里的杯子大小差了 13%、帽檐一张有一张没有、提示词里左右写反了。

新开一个 agent，只给它下面这些材料（路径），不给你的结论：

```
你是审核，只读不改。这个镜头马上要提交视频生成，花的是真钱。
材料：[提示词文件]、[首帧]、[尾帧]、[设定图]、[分镜表这一镜]、[配色规则]、[风格特征清单 style.md]。
逐项核对，放大看图（可以用 Python 裁剪放大、叠加对比）：
1. 提示词的每句话和两张图对得上吗？（位置、左右、颜色、人数、道具数量、衣服、表情）
2. 两张图的机位、大小、背景一致吗？
3. 和设定图、配色规则、风格特征清单、前后镜头对得上吗？
4. 动作现实吗？每个动作的原因写了吗？手放在哪？
5. 模型可能在哪里出错？（同时动作、凭空出现、长脸、走反方向、歧义词，以及 model-quirks.md 里这个模型的已知问题）
最后只写"通过"或"不通过"。不通过就逐条列出要改什么。
```

审核不通过 → 改提示词或图 → 存新版本 → 重新审核。通过后向用户报价（镜头、模型、分辨率、秒数、预估金额、累计 / 总预算），用户同意才提交。

## 第 6 步：生成

### 省钱技巧

- 用 720p（或该模型较低的档位）生成，后期再放大到 1080p。
- 不单独拍测试片，直接拍第一个正式镜头，能用就赚了。
- 新的做法（新画风、新的镜头类型）先拿一两个最难的镜头试，行得通再全部提交。
- 贵的模型只留给复杂镜头。不太考验模型能力的镜头用便宜的就够。
- 声音要听过才能用：你听不到声音，所以要请用户听。不确定的就不用片段自带的声音，后期另外加。

### 拿到片段后

1. 用 `scripts/extract_frames.sh` 抽帧，逐帧看：人数、道具数量、脸有没有变形、走的方向、有没有凭空出现的东西、首尾帧有没有突跳、颜色有没有漂移。
2. 把结论写进 `review-log.md`，并明确告诉用户：你只看了抽出来的帧，动态的流畅度和声音需要用户自己看、自己听。

### 发现问题，按这个顺序处理

1. **能不能剪掉？** 问题只出现在开头或结尾几帧，直接剪掉。
2. **能不能用代码修？** 比如变速、补推镜、调色、定格、遮挡局部。修不好再考虑重拍。
3. **重拍**：先改提示词或首尾帧，再重拍。原样再拍一次，大概率还是错的。只重拍这一镜，旧片段不删，最后一起挑。
