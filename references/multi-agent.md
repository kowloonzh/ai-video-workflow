# 四线程协作模式（可选）

用户希望自己少盯一点、让流程尽量自动往前推时使用。你当**主做**，再开三个子 agent，四个一起配合，一直做到片子做完，或者账户欠费为止。

## 开工前向用户确认

- 用户说过的话在哪里（对话记录或要求文件的路径；Claude Code 的记录在 `~/.claude/projects/` 下）。至少要有 `00-brief.md`。
- 总预算 ¥X。代理只能在这个额度内批准提交。
- 哪些交互节点（见 SKILL.md 的 N0–N11）仍然必须用户亲自确认。默认 N1 故事方向、N2 故事定稿、N4 画风必须用户亲自拍板，代理不能替；其他节点由代理按偏好决定，但要把决定汇总留给用户回来看。用这个模式前，先用一次提问让用户勾选哪些节点交给代理。

## 角色

| 角色 | 负责什么 | 权限 |
|---|---|---|
| 主做（你） | 所有制作 | 读写 |
| 审核 | 每一步都挑错；提交生成视频之前必须明确写"通过" | 只读 |
| 监督 | 读完用户说过的所有话，整理成要求清单；每一步都检查有没有人（包括主做）忘了要求 | 只读 |
| 代理 | 读完用户说过的所有话，整理成用户偏好；主做和审核拿不准，或者要提交生成视频时，按用户偏好替用户做决定，并写明依据和把握 | 只读；只能在总预算内批准提交，超预算就停下来等用户 |

审核每次都用一个新的子 agent，只给它材料，保持"第一次看"的视角。监督和代理可以长期保留（用 SendMessage 续用），因为它们的价值就在于记住用户的话。

## 配合顺序

1. 主做每完成一步，先交给审核，再交给监督。
2. 有分歧（主做和审核意见不一致、要求有冲突、拿不准用户会怎么选）就交给代理决定。
3. 所有决定和花费都记进 `review-log.md`，格式：时间 / 步骤 / 谁决定 / 决定内容 / 依据 / 花费 / 累计花费。用户回来可以推翻任何决定。
4. 不充值，不买额度。欠费就停，先把已有的片段粗剪出来给用户看。

## 用户可以直接发的提示词

```
这支片子用四线程来做。你当主做，再开三个子 agent，四个一起配合，一直做到片子做完，或者账户欠费为止。
我说过的话在：[对话记录或者要求文件的路径]。
总预算：¥[金额]。

分工：
- 主做：就是你，负责所有制作。
- 审核：开一个子 agent，只挑错，不改文件。每一步都要查，提交生成视频之前必须明确写"通过"。
- 监督：开一个子 agent，读完我说过的所有话，整理成要求清单。每一步都查有没有人忘了要求，包括你。
- 代理：开一个子 agent，读完我说过的所有话，整理成我的偏好。你和审核拿不准，或者要提交生成视频时，由它按我的偏好来决定，并写明依据和把握。它只能在总预算内批准提交，超过预算就停下来等我。

配合的顺序：
1. 你每做完一步，先交给审核，再交给监督。
2. 有分歧就交给代理决定。
3. 所有决定和花费都记进审核记录，我回来可以推翻任何决定。

不充值，不买额度。欠费就停，先把已有的片段粗剪出来给我看。
```
