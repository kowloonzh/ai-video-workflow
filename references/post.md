# 第 7–8 步：后期与全片复核

后期全部用代码做（ffmpeg + Python），脚本存进 `07-post/`。这样改一个参数就能整片重跑，也能追溯每一步做了什么。

## 第 7 步：拼接、转场、调色、放大

### 处理顺序

1. **逐片段预处理**：剪掉坏帧（开头过锐的帧、结尾突跳）、定格、变速对拍点、补推镜、按自己的首帧校色（针对会漂色的模型）。
2. **调色**
3. **放大**
4. **拼接和转场**
5. **配乐 / 音效 / 字幕**
6. **导出**

中间文件一律用无损格式（如 FFV1 的 mkv 或 PNG 序列），只在最后交付时压一次，避免多次压缩画质损失。

### 具体要求

1. **转场**：写清楚哪一镜到哪一镜、用什么东西盖屏或带过去（飘过的物体、人物走过镜头前、快速横摇）。需要运动模糊时，把相邻帧细分成 8–16 份做插值再混合，模拟半帧快门（180°）。
2. **调色**：按故事分段调。只调彩度和亮度，**不动色相**；强调色受保护；肤色不变。不加颗粒、柔光、暗角（除非画风要求）。参照色表。
3. **色彩空间**：Seedance 的 mp4 按 BT.601 解码；交付文件标 BT.709。其他模型先用 `ffprobe` 看 `color_space` / `color_primaries` / `color_transfer`，没标的按分辨率常规处理，并在复核时对比首帧颜色确认。示例：
   ```bash
   ffmpeg -i in.mp4 -vf "scale=in_color_matrix=bt601:out_color_matrix=bt709" \
     -color_primaries bt709 -color_trc bt709 -colorspace bt709 ...
   ```
4. **放大**：720p 用 lanczos 放大到 1080p，加轻微锐化（例如 `scale=1920:1080:flags=lanczos,unsharp=5:5:0.5`）。不要整段插帧（容易产生果冻和变形），只在转场等局部需要的地方用。
5. **卡点**：拍点只在**原曲**上测（用 librosa 等做节拍检测，或者按 BPM 计算），不要在剪过的文件上测。按小节对齐切点和关键动作。
6. **声音**：片段自带的声音要用户听过才能用；不确定就静音，另外加音效。

### 检查

做完抽查每个切点前后各 3 帧：有没有黑帧、闪帧、重复帧、颜色跳变、尺寸不一致。用 `scripts/extract_frames.sh` 或 ffmpeg 的 `select` 滤镜取帧。

### 给用户的后期提示词模板

```
用代码做后期：
1. 转场：[哪一镜到哪一镜，用什么东西盖屏或带过去]。运动模糊切 8–16 份，半帧快门。
2. 调色：按故事分段。只调彩度和亮度，不动色相，强调色受保护，肤色不变。不加颗粒、柔光、暗角。
3. Seedance 的 mp4 按 BT.601 解码，中间文件用无损格式，交付标 BT.709。
4. 放大：720p 用 lanczos 放大到 1080p，加轻微锐化。不用整段插帧。
5. 按小节卡点：拍点只从原曲上测，不要在剪过的文件上测。
做完抽查切点前后 3 帧。
```

## 第 8 步：全片复核与交付

粗剪（N9）确认后，进入"**打分评审 → 修改**"循环。思路借鉴自 mg-styles-15 的 rubric：只挑错能拦住硬伤，但推不动片子变好；打分加上按影响排序的修改清单，才能告诉你下一步最值得改哪里。

### 8.1 先自评（不给评审看）

主做先给成片按下面 8 个维度打分，写出自己认为最弱的 3 处，记进 `review-log.md`。这份自评**不交给评审 agent**，只用来和评审结果对照：差距很大的维度，往往就是你自己看不出的盲点。

### 8.2 独立评审

每一轮都新开一个评审 agent。给它这些材料：成片文件、`00-brief.md` 里的输出规格（时长、画幅、分辨率、帧率、响度目标）、`03-style/style.md`（画风那句话和风格特征清单）、色表。**不给**故事、分镜、自评和上一轮的评审结果，这样它对故事是否讲清楚的判断才是"第一次看"，打分也不会被上一轮锚定。

评审提示词：

```
你是资深的短片评委，这支 AI 短片不是你做的。请严格、具体地评审，目标是让它达到精品水平。客气没有用，具体才有用。
材料：[成片]、[输出规格]、[画风与风格特征清单]、[色表]。

1. 认真看片：
   - 每 0.5 秒抽一帧拼成总览图；
   - 最快的动作、最重要的动作和高潮处抽连续帧；
   - 每个切点前后各 3 帧；
   - 5–8 个关键时刻取全分辨率帧，放大看细节：脸、手、边缘、文字、色带、闪烁、多余的东西。
2. 先写你看懂的故事和这支片想表达什么，再列出看不懂的地方。
3. 查规格：时长、分辨率、帧率是否符合；有没有声音；响度是否在目标 ±1 LU 内，true peak ≤ −1 dBTP；有没有意外的黑帧、静止段或闪帧；重要动作是否落在音乐重拍上。
4. 按 8 个维度各打 1–10 分。锚点：5 = 能看但一眼就是 AI 拼凑；6 = 普通 AI 短片水平；7 = 扎实，可以发布；8 = 精品，头部创作者水平；9 = 能进奖项短名单；10 = 世界顶级。多数初版应该在 5–7 分之间，不要虚高。
   - 故事清晰度：第一次看能不能看懂，一句话主题能不能被感受到
   - 开头抓人：前 2 秒有没有钩子，有没有让人想看下去
   - 镜头语言与构图：机位、景别变化、运镜的理由、每一帧截图好不好看
   - 画风与角色一致性：是否对照风格特征清单逐条成立；脸、服装、配饰、颜色是否全片一致
   - 动态自然度：有没有同时动作、凭空出现、瞬移、脸或手变形、走反方向、嘴自己在动
   - 剪辑节奏与卡点：快慢对比、转场是否由画面里的东西带过去、动作和音乐是否对上
   - 声音：配乐和音效是否合适、是否同步、混音是否干净（如果你无法听，就明确写"未评估"，不要打分）
   - 技术：规格、黑帧、闪烁、色彩跳变、画质（放大后的锐度、色带、压缩块）
5. 给 5–10 条修改意见，按对整体观感的影响从大到小排序。每条写：
   - 时间码 / 帧号
   - 问题（看得见的现象）
   - 为什么重要
   - 具体怎么改（技法和数值：剪掉哪几帧、变速多少、转场用什么、调色调哪里、字幕怎么排）
   - 成本类别：A = 后期代码能改；B = 需要重画首尾帧并重拍这一镜（写出镜号和秒数）；C = 需要改故事或分镜
   宁可少几个大改动，也不要一堆小毛病。影响相近时，优先列成本低的。至少一条要提升惊艳度，而不只是修细节，最好是 A 类。
6. 单独列出致命问题：看起来像廉价的 AI 模板、角色明显前后不一致或脸变形、文字或文案错误、穿帮、任何不符合规格的地方。
7. 明确写出你查不了的东西（真实的动态手感、声音）。
返回：评分表、致命问题、修改清单。
```

规格可以用 ffmpeg 量出来，评审 agent 和主做都可以用：

```bash
# 响度与 true peak
ffmpeg -i film.mp4 -af ebur128=peak=true -f null - 2>&1 | tail -12
# 黑帧、静止段
ffmpeg -i film.mp4 -vf "blackdetect=d=0.05:pix_th=0.10" -an -f null - 2>&1 | grep black_
ffmpeg -i film.mp4 -vf "freezedetect=n=0.003:d=0.5" -an -f null - 2>&1 | grep freeze_
# 每 0.5 秒一帧的总览图（16:9 成片按 6 列；6x5 一张图覆盖 15 秒，更长的片子会自动输出多张）
ffmpeg -i film.mp4 -vf "fps=2,scale=480:-1,tile=6x5" contact_%02d.png
```

### 8.3 交互节点 N10：评审轮次

把这些拿给用户：评分表（评审分数和你的自评并排）、致命问题、修改清单（每条标成本类别，B 类写出镜号、秒数和预估金额），以及你的建议：哪些改、哪些不改，理由是什么。一次问清：

- 改哪些？（默认：全部致命问题 + 高影响的 A 类）
- B 类重拍花不花这笔钱？
- 这一轮改完后，要不要再评审一轮？

**目标与停止条件**：默认目标是每个维度 ≥ 8 分。达到目标、已经改满 2 轮，或者用户说够了，就停。超过 2 轮要用户明确同意。

### 8.4 按评审修改

回到主做（你自己）：

1. 先把当前成片和后期脚本存为第 N 版，不覆盖。
2. 落实用户同意的每一条。你有把握找到更好的方案时可以替换，但要说明理由。看到更大的提升机会（尤其是惊艳度）可以超出清单，同样先告诉用户。
3. **评审认可的优点不能改坏**。改完对比一下上一版的同一位置。
4. A 类直接在后期脚本里改。B 类按 `video-prompt.md` 的流程走：改提示词或首尾帧 → 提交前审核 → 报价 → 用户同意 → 只重拍这一镜。C 类回到对应阶段，改完需要用户重新确认那个阶段。
5. 全分辨率重新导出，重新跑规格检查，抽帧确认修改真的生效了。
6. 报告哪些意见改了、哪些没改、为什么，记进 `review-log.md`。

然后回到 8.2，开一个新的评审 agent 再评一轮。

### 8.5 收尾

- 最后一轮的分数、你看不到听不到的部分，一并交给用户。
- 提醒用户亲自完整看一遍、听一遍。

### 交付

- 成片：H.264 或 H.265，标 BT.709，码率够用（1080p 建议 ≥ 12 Mbps），音频 AAC 320k。
- 写 `lessons.md`：
  - 画风那句话和设定描述
  - 效果好的提示词（附镜号）
  - 犯过的错、原因、修法
  - 花费汇总（每镜抽了几次、总花费）
- 发现模型新的稳定毛病，问用户要不要追加到本 skill 的 `references/model-quirks.md`。
